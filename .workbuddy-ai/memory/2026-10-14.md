- 交叉编译配置：新增项目级 `.cargo/config.toml`（CC/AR/CFLAGS 指向 NDK `clang.exe`/
  `llvm-ar.exe` + `--target=aarch64-linux-android21`；linker = `clang++.exe` + link-arg）。
  NDK 的 per-ABI wrapper `aarch64-linux-android21-clang` 在 Windows 无扩展名、不可直接执行，
  必须用通用 clang.exe + 显式 --target。cargokit 自带这些设置，手跑 cargo 才需要它。
- 验证脚本：`target/verify-preview.ps1`（check → test → build apk → 安装 → 联调 → 30s 帧率实测
  + gfxinfo + top），设计成在用户的 shell 里一键跑完。
- 已修的两个真实编译错误（用户跑出来的）：① `External` 含裸指针做 static 需手写 unsafe impl
  Send+Sync（E0277）；② `pub use crate::android::preview_surface::*` 报 E0603——跨两级私有模块
  不可达，需 `pub(crate) mod preview_surface;`（既有 `crate::source` 之所以可行是因为只跨一级）。
  教训：本项目里"私有模块 + pub 项"的门面模式只对一级路径成立。③ dead_code 警告：Stream.external
  只用于持有引用直到 Drop，需 `#[allow(dead_code)]`（同 session 字段）；④ 我新加的 core 测试里
  `unbounded_channel()` 推不出类型 → 写 `::<PreviewFrame>`。
- **既定失败（与本次改动无关）**：`clock::tests::trims_trailing_zeros_of_the_nanosecond_fraction`
  在 Windows 必挂 —— `SystemTime` 只 100ns 粒度，123_456_789ns 存进去读回 123_456_700，尾零被裁。
  CI 在 Linux（纳秒精度）能过。已把断言改成 100ns 可精确表示的值（100_000_000 / 123_456_000 /
  123_456_700），保住"裁尾零"意图。若用户不想动无关文件可回滚 clock.rs。
- 我新加的 core 测试全部通过（旋转先行 fit 不变量、publish_rgba 直通与拒绝语义）。

## 真机跑通后的行为修正（重要）
- 构建/安装成功，预览**流畅**（卡顿解决）。
- **旋转错了 90°**：竖屏预览显示横屏画面（内容被多转了一次顺时针 90）。原因：camera2 写入
  SurfaceTexture 的缓冲自带 transform 矩阵，**引擎采样时已经把传感器方向修正好了**，图片到达
  Dart 时已正立；我又用 `RotatedBox(quarterTurns=1)` 补了一次 → 双重修正。
  → 修正：① `preview_texture.dart` 的 `quarterTurns()` 对 Android 直接返回 0（机制保留，注释
  说明设备若不填 transform 矩阵则需改回传感器 quarter turns）；② `preview_surface::size()`
  上报**转向后**的尺寸（90/270 换边），否则 AspectRatio 仍是横屏比例。
- 教训（与之前的判断相反）：**Android 的 SurfaceTexture 路径不需要再做传感器旋转补偿**，
  而像素路径（`to_rgba` 的 90 分支）需要——两者方向语义不同，别照搬。
